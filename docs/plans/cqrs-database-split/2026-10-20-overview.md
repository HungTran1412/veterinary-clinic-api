## Hiện trạng và thiết kế

Có hai DbContext cùng DefaultConnection. Write context audit SaveChangesAsync; read context có model giống write. Các command dùng write context, query dùng read. Không có test project/Wiki/AGENTS.md trong repo; dùng chỉ dẫn người dùng, README và source. Stored procedure helper luôn dùng DefaultConnection. Có transaction nhiều SaveChanges trong đặt lịch và hóa đơn. Hangfire/seeder có tác động DB khi chạy API, vì vậy chỉ build và test biệt lập.

Tái sử dụng hai context. Outbox ở Write DB ghi danh sách loại entity và primary key, không lưu bản sao mật khẩu/token. Sau business SaveChanges lấy identity thực và ghi Outbox trong cùng local transaction. Worker serialize bằng SQL Server application lock, đọc mọi pending theo batch (không high-water mark), đọc lại trạng thái committed hiện tại, áp dụng lên Read DB trong transaction, rồi đánh dấu hoàn tất. Không dùng snapshot sự kiện cũ nên replay/commit lệch thứ tự vẫn hội tụ. Đồng bộ bao phủ tất cả entity business mapped, gồm khóa ghép; không đồng bộ chính Outbox/Hangfire/migration history.

`ReadModelSynchronization:Enabled` mặc định false để không truy cập bảng chưa chuẩn bị. Khi tách hai DB phải bật đồng bộ; cấu hình thiếu hoặc cùng đích phải fail fast. Duy trì DefaultConnection fallback chỉ ở chế độ một DB. Read context dành riêng query; projection dùng context ghi replica nội bộ để không audit hay phát lại Outbox. Query cache bypass khi đang split để tránh nạp lại bản cũ trong khoảng replica lag. Command tiếp tục đọc authoritative Write DB.
